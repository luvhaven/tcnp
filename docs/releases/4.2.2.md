# 4.2.2 — Dashboard relationship fix

Supabase returned PGRST201 (ambiguous relationship) for the dashboard's journey queries: journeys now relates to papas through both journeys_papa_id_fkey and journey_papas. Explicitly selecting the primary Papa foreign key resolves the failure without changing records, schema, permissions, or the returned Papa object shape. The dashboard journey-alert widget uses the same explicit relationship.

Read-only live verification reproduced the original HTTP 300 failure and confirmed HTTP 200 for the corrected embedding, without retrieving records. Added a regression assertion for both dashboard query sites and the alert widget.

## Framework upgrade assessment

Next.js remains unchanged in this hotfix. The npm latest tag and official documentation report 16.3.5 at assessment time. Upgrade separately using a preview deployment and rollback checkpoint:

1. Audit React 19 compatibility; installed React Leaflet 4.2.1 declares React 18 peer dependencies.
2. Keep webpack initially (`next dev --webpack`, `next build --webpack`) while verifying the webpack-based next-pwa integration and custom alias. Next 16 defaults to Turbopack.
3. Migrate next lint to the ESLint CLI and align ESLint/config versions.
4. Audit async request APIs, middleware/proxy behavior, route handlers, and framework configuration using the official guide: https://nextjs.org/docs/app/guides/upgrading/version-16.
5. Verify authentication, permissions, realtime chat, maps, uploads, training embeds, offline queue replay, and installed PWA updates before promoting the preview.

No zero-regression guarantee is possible; the upgrade has not been performed by this hotfix.
